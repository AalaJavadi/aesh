# AESH v3.23 — راهنمای نصب

این نسخه روی **AESH v3.22** ساخته شده است. امکانات قبلی پنل، اعضا و مدیریت حذف نشده‌اند.

## ۱. آپلود روی GitHub

1. داخل GitHub Desktop مخزن `aesh` را باز کنید و برای اطمینان `Fetch origin` را بزنید؛ اگر `Pull origin` نمایان شد، آن را نیز انجام دهید.
2. ابتدا یک نسخه پشتیبان از پوشه مخزن بگیرید؛ از پوشه مخفی `.git` نسخه بگیرید و **هرگز آن را حذف نکنید**.
3. فایل ZIP اصلاحات را Extract کنید. فایل‌ها و پوشه‌های **داخل** آن را در پوشه اصلی مخزن کپی کنید؛ نام فایل `index.html` باید مستقیماً در ریشه باشد، نه داخل یک پوشه اضافه.
4. فقط فایل‌های هم‌نام را جایگزین کنید؛ پوشه `.git` را پاک نکنید.
5. در GitHub Desktop تغییرات را بررسی و سپس با Summary دلخواه مثلاً `AESH v3.23 fixes`، گزینه `Commit to main` و پس از آن `Push origin` را بزنید.

> پیشنهاد: از ZIP «فقط اصلاحات» برای بروزرسانی سایت فعلی استفاده کنید؛ فایل کامل هم برای پشتیبان موجود است.

## ۲. فعال‌سازی لایک و دیسلایک بدون حساب (الزامی)

- با حساب مدیر به Supabase بروید: **SQL Editor → New query**.
- متن فایل `sql/aesh_v323_guest_votes.sql` را کپی و Run کنید.
- اگر با موفقیت اجرا شد، صفحه نمونه‌کار را تازه‌سازی کنید. افراد مهمان می‌توانند لایک یا دیسلایک کنند و رأی از طریق Supabase ذخیره می‌شود.
- **رمز عبور، secret key یا service_role را داخل فایل‌های سایت یا GitHub قرار ندهید.**

سیستم مهمان یک شناسه تصادفی در همان مرورگر ذخیره می‌کند. رأی‌ها روی سرور ذخیره می‌شوند؛ اما با پاک‌کردن داده‌های مرورگر یا تعویض مرورگر، امکان ساخت شناسه جدید وجود دارد. بنابراین بدون احراز هویت نمی‌توان «فقط یک رأی برای هر شخص» را کاملاً تضمین کرد.

## ۳. تصویر شاخص لینک آثار جدید (الزامی برای تصویر درست در پیام‌رسان‌ها)

عکس شاخصِ صفحات قدیمی همراه فایل‌های سایت قابل نمایش است. برای آثار جدیدی که از پنل و Supabase منتشر می‌شوند، یک صفحه واقعی Open Graph تولید می‌شود تا پیام‌رسان‌ها تصویر **همان اثر** را بخوانند.

- بعد از Push وارد مخزن `aesh` در GitHub.com شوید.
- از بالا **Settings → Pages** را باز کنید.
- زیر **Build and deployment** گزینه **Source** را روی **GitHub Actions** قرار دهید.
- وارد زبانه **Actions** شوید و کار `Deploy AESH with artwork previews` را یک‌بار با **Run workflow** روی شاخه `main` اجرا کنید؛ منتظر تیک سبز بمانید.
- دفعه‌های بعد با هر Push و سپس تقریباً هر ۳۰ دقیقه یک‌بار، نسخه جدید تصاویر اشتراک آثار منتشرشده بررسی و به‌روزرسانی می‌شود. زمان‌بندی GitHub دقیق نیست و ممکن است تأخیر داشته باشد.

چنانچه کار در زبانه Actions خطا داد، ابتدا خروجی همان اجرا را بررسی کنید؛ در این حالت آدرس و کلید عمومی در `assets/aesh-config.js` و دسترسی به تابع‌های `aesh_public_works` و `aesh_public_profiles` در Supabase باید درست باشد. نسخه آخرِ منتشرشده معمولاً محفوظ می‌ماند.

## ۴. لینک آثار تازه و قبلی

- مدیر: اثر جدید را ثبت می‌کند؛ شناسه لینک از عنوان فارسی + یک شناسه کوتاه یکتا ساخته می‌شود.
- استاد/هنرجو: اثر جدید را ارسال می‌کنند و پس از **تأیید مدیریت**، لینک خودکار ساخته می‌شود.
- اگر قبلاً اثری منتشر شده اما `slug` ندارد، مدیر از قسمت «بررسی و تأیید آثار» آن اثر را روی «منتشرشده» بگذارد و «ذخیره تصمیم» بزند تا لینک اختصاصی ساخته شود.
- برای تصویر شاخص اثر تازه در تلگرام/دیگر پیام‌رسان‌ها تا پایان کار GitHub Actions منتظر بمانید؛ بعضی پیام‌رسان‌ها پیش‌نمایش لینک را در حافظهٔ موقت نگه می‌دارند.

## ۵. ورود اعضا

نشست در فضای `localStorage` مرورگر ذخیره می‌شود و پس از بستن صفحه باقی می‌ماند؛ ورود مجدد فقط در صورت خروج از حساب، حذف حافظه مرورگر، لغو یا انقضای نشست لازم است. برای دستگاه عمومی حتماً «خروج از حساب» بزنید.

## ۶. تست نهایی

1. یک حساب هنرجو یا استاد را وارد پنل کنید، مرورگر را ببندید و دوباره `https://aesh.ir/members/` را باز کنید.
2. یک نمونه‌کار تازه بارگذاری، سپس از پنل مدیر آن را تأیید کنید. آدرس اختصاصی و نمایش ابعاد روی کارت نمونه‌کار را بررسی کنید.
3. در مرورگر دیگر، بدون ورود، یکی از آثار را لایک کنید؛ صفحه را ببندید و باز کنید و مطمئن شوید همان رأی و شمارش نمایش داده می‌شود.
4. آدرس هر استاد، هنرجو و اثر را برای تست عکس شاخص در پیام‌رسان به اشتراک بگذارید.
