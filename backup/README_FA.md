# بکاپ رایگان AESH از Supabase — بدون SQL و Python

این ابزار رایگان **فقط اطلاعات را می‌خواند** و هیچ جدول، حساب یا فایل Supabase را تغییر نمی‌دهد. برای استفاده روی کامپیوتر ویندوزی خودتان:

۱. اگر `pg_dump` و `pg_restore` روی ویندوز نصب نیستند، ابزارهای رایگان PostgreSQL را از سایت رسمی `https://www.postgresql.org/download/windows/` نصب کنید. گزینه Command Line Tools لازم است؛ نیازی به ساخت دیتابیس محلی ندارید.

۲. در داشبورد Supabase، روی **Connect** کلیک کنید و Host، Port و User دیتابیس را ببینید. در **Project Settings / Database** رمز اتصال دیتابیس را در اختیار داشته باشید. اتصال ممکن است با `session pooler` کار کند و آن زمان باید Host/Port/User مربوط به همان اتصال را وارد کنید. اگر رمز را ندارید، خودسرانه آن را تغییر ندهید.

۳. فایل **`BACKUP_SUPABASE_FREE.cmd`** را دو بار کلیک کنید. اطلاعات اتصال و رمز دیتابیس را فقط در پنجره‌ای که روی **کامپیوتر خودتان** باز شده وارد کنید. رمز مخفی دریافت می‌شود. برای پشتیبان‌گیری فایل‌ها، جواب `Y` بدهید و Project Ref و کلید خصوصی `service_role` را از **API Settings** داخل همان برنامه وارد کنید. این کلید حساس است؛ هرگز آن را برای کسی ارسال نکنید یا در GitHub قرار ندهید.

۴. برنامه بکاپ دیتابیس را به شکل `database_full.dump` می‌سازد و با `pg_restore --list` بررسی می‌کند آرشیو قابل خواندن است. Storage را به‌صورت blob خصوصی با فایل `storage_manifest.json` و SHA-256 تک‌تک فایل‌ها ذخیره می‌کند. محل خروجی: `Documents/AESH_PRIVATE_BACKUPS/supabase_YYYYMMDD_HHMMSS/`.

۵. اگر فایل `BACKUP_INCOMPLETE.txt` ایجاد شده، **بکاپ کامل نیست**؛ خطا را رفع کنید و دوباره اجرا کنید. حتی اگر خطایی نباشد، `BACKUP_FILES_CREATED_NOT_RESTORE_TESTED.txt` تأکید می‌کند که **بازگردانی در یک پروژه آزمایشی مستقل باید توسط مدیر فنی انجام و شمارش رکوردها تطبیق داده شود**. صرف ساخت فایل، تأیید بازیابی نیست.

## چرا فایل ZIP سایت کافی نیست؟

ZIP مخزن GitHub حاوی رکوردهای خصوصی `auth.users`، داده‌های واقعی و شیءهای Storage نیست. دستور ساده `supabase db dump` ممکن است بعضی اسکیمای داخلی را به‌صورت پیش‌فرض کنار بگذارد؛ `pg_dump` کاملِ این ابزار با حساب مجاز، روش دیگری است، اما همچنان باید با بازیابی آزمایشی صحت آن بررسی شود. همچنین فایل‌های Storage در دیتابیس ذخیره نمی‌شوند و دانلود مستقل لازم دارند.

## امنیت

- هرگز پوشه بکاپ، فایل `database_full.dump` یا `storage_manifest.json` را در پوشه مخزن `aesh` کپی نکنید.
- چون فایل‌ها شامل اطلاعات حساس‌اند، از درایو رمزگذاری‌شده یا یک حافظه امن استفاده کنید.
- این اسکریپت روی Supabase اصلی **INSERT/UPDATE/DELETE** انجام نمی‌دهد.
- این اسکریپت در محیط گفتگو روی حساب واقعی اجرا نشده و روی ویندوز واقعی هم هنوز تست نشده است؛ نخست روی سیستم خودتان نتیجه را بررسی کنید.

منابع رسمی: https://supabase.com/docs/guides/platform/migrating-within-supabase/backup-restore و https://www.postgresql.org/docs/current/app-pgdump.html
